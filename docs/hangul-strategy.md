# 한글 글꼴 공급 전략

## 결론

완성 번역 corpus는 요구 글리프 445개, 완성형 한글 379개이므로 단일 255셀 atlas를
탈락시켰다. 현재 선택은 **완성형 한글 작업 집합 + 공용 decoder 재매핑 + 정적 2뱅크
atlas**다. 번역 문자열은 글자당 고정 2바이트 사용자 코드를 쓰고 decoder 반환값의
bit 8로 bank, 하위 8비트로 cell을 전달한다.

`FONT-TWO-BANK-POC-001`에서 이 ABI가 실제 `0x80042F84` builder까지 도달해 bank 1
`tpage=0x1E`, cell `DE`의 U/V를 만드는 것은 런타임 PASS했다. 최종 두 번째 atlas의
저장·업로드·전역 상주는 아직 OPEN이며, 자세한 결과는
[two-bank-font-poc.md](two-bank-font-poc.md)에 기록했다. 글꼴 예산에 맞추기 위한 의미
훼손이나 강제 축약은 허용하지 않는다.

기계 판정은 `work/analysis/hangul_strategy_001.json`, 재현 도구는
`workspace/scripts/analyze_hangul_strategy.py`다.

## 확정 제약

| 항목 | 값 | 판정 |
| --- | ---: | --- |
| atlas | 256×256 4bpp | 16×16 글리프 256셀 |
| 기존 사용 셀 | `00`–`FE`, 255셀 | 현재 안전한 직접 재사용 셀 0 |
| `FF` | blank/fallback | 실제 `8140` 전각 공백이 소비 |
| decoder 입력/출력 | 2바이트 → 8비트 셀 | 단일 atlas 주소 한계 256셀 |
| UV | `u=(cell&0x0F)<<4`, `v=cell&0xF0` | 행·열 각 4비트 |
| image VRAM | `(960,256)`, `64×256` words | 끝점 `(1024,512)` |
| PS1 VRAM | `1024×512` words | 우측·하단 동시 경계 도달 |
| 확인된 reader unknown | 0 | 공용 decoder hook 적용 범위 폐쇄 |
| 확인된 정적 원문 | 324개 | 번역 SSOT·글리프 census의 시작 집합 |

따라서 기존 TIM을 오른쪽이나 아래로 늘리는 **제자리 atlas 확장**은 물리적으로
불가능하다. 이미지 데이터만 다른 위치에 추가해도 현재 8비트 셀 값과 UV 계산은 두 번째
페이지를 표현하지 못하므로 decoder/builder 변경 없는 확장 역시 불가능하다.

Options 캡처는 해당 세션에서 기존 atlas가 업로드·소비됐음을 증명하지만, 게임 전체에서
두 번째 256×256 페이지가 상주할 안전한 VRAM 영역을 증명하지 않는다. 추가 뱅크 위치는
대표 게임 상태별 VRAM 관측 후에만 확정한다.

## 비교 판정

| 후보 | 판정 | 이유 |
| --- | --- | --- |
| 기존 일본어 코드 직접 재사용 | 배제 | 도달 가능한 셀이 모두 점유됐고 `FF`도 공백으로 사용됨 |
| 제자리 atlas 확대 | 배제 | VRAM 경계와 8비트 셀/UV 한계를 동시에 넘음 |
| decoder 재매핑 + 고정 atlas 재구성 | 1순위 | 세 reader 경로를 한 훅으로 처리하고 기존 움직임·primitive ABI를 보존 |
| 정적 다중 뱅크 atlas | 조건부 fallback | 용량은 늘지만 bank 전달, tpage, VRAM 상주 검증이 추가됨 |
| 자모 조합 | 첫 구현에서 배제 | 한 글자당 여러 primitive가 필요해 타이틀 UV 반전·움직임 소비자까지 영향 |
| eviction형 동적 cache | 첫 구현에서 배제 | primitive 생존 시간과 cache 교체 안전성이 확인되지 않음 |

## 1순위 설계 계약

- 문자열 저장은 기존과 같은 NUL 종료, 글자당 고정 2바이트를 유지한다.
- 한국어 코드 공간은 번역 SSOT에서 결정론적으로 생성하고 중복 배정을 금지한다.
- decoder hook은 한국어 코드만 새 매핑 표로 보내며 필요한 보존 코드의 기존 동작을
  명시적으로 유지한다.
- `00`–`FE`의 255셀은 일본어 원본의 “빈칸”을 찾는 방식이 아니라, 전체 번역 corpus와
  보존 기호 목록으로 새로 구성한다. `FF`는 blank/fallback으로 남긴다.
- 번역 빌드는 `고유 한글 + 숫자·라틴·구두점·제어상 필요한 보존 기호 <= 255`를
  강제한다. 초과 시 산출물을 만들지 않는다.
- 그래픽에 구운 문자열은 이 255셀 예산과 별도 카탈로그로 관리한다.

## 다중 뱅크 fallback의 최소 PoC

용량 게이트를 넘으면 256×256 4bpp 정적 atlas 두 장과 명시적 `bank+cell` 매핑을 만든다.
PoC는 다음을 모두 증명해야 한다.

1. 대표 타이틀·옵션·게임플레이 상태에서 충돌하지 않는 두 번째 VRAM 페이지와 업로드
   수명을 확인한다.
2. 현재 8비트 decoder 결과를 넘어 bank 정보를 primitive 생성 지점까지 전달한다.
3. 확인된 범용 renderer, 단일 글리프 renderer, 타이틀 builder 모두 올바른 tpage와 UV를
   사용한다.
4. 타이틀의 UV 정점 반전과 춤추는 이동, 16글자 경계, clipping, 화면 전환을 영상으로
   검증한다.
