## 핵심 설계 — 반드시 알아야 할 3가지

### 1. 글꼴: 셀당 글자 2개 패킹

원본 4bpp 아틀라스는 셀 하나의 **비트플레인 4장**에 같은 글자의 흔들림 프레임
4장을 담고, 공용 primitive builder가 전역 카운터로 팔레트 0–3을 골라 낙서풍
흔들림을 만든다. CLUT을 쓰는 코드는 ARA `0x80043004` **단 한 곳**이고 모든 텍스트
경로가 이 builder를 호출한다.

그래서 **셀당 글자 2개 × 흔들림 2프레임**으로 재정의했다.

```
플레인 0,1 = 글자 A (bank 0)      플레인 2,3 = 글자 B (bank 1)
팔레트 = (bank << 1) | ((전역카운터 >> 2) & 1)
용량 = 255셀 × 2 = 510자   (현재 460자 사용)
```

덕분에 **두 번째 VRAM 페이지가 불필요**해졌다. 아틀라스는 기존 `(960,256)`을 같은
크기로 교체할 뿐이다. (이전 세션의 2뱅크 VRAM 감사 `FONT-TWO-BANK-VRAM-001~003`은
근거로만 보존하며 배포 의존성이 아니다.)

### 2. 인코딩과 decoder

문자열을 자체 인코딩으로 재작성하므로 decoder가 7개 명령으로 축소됐다.

```
code   = 0x8000 + ((bank << 8) | cell)
retval = code - 0x8000        ; 범위 밖이면 blank 셀 0xFF
```

**중요한 부작용**: 번역 목록에 없는 문자열은 옛 Shift-JIS 코드가 범위 밖이라
**빈칸으로 렌더된다**. 즉 **화면의 빈칸 = 미번역 문자열 탐지기**다. 플레이 중
글자가 있어야 할 자리가 비어 있으면 그 자리에 누락 문자열이 있다.

### 3. 문자열은 버튼 아이콘 마커로 분절돼 있다

조작 설명 등은 한 문자열 안에 **2바이트 ASCII 마커**(`0x30xx`·`0x31xx`, 예: `"0P"`,
`"1D"`)가 섞여 버튼 아이콘을 표시한다.

```
もくひょうを [0P] ほうこうキー [00] でしてい ␀
```

문자열 스캔은 **마커를 경계로** 조각을 잡아야 한다. NUL로 끝나는 마지막 조각만
잡으면 문장 앞부분이 미번역으로 남아 빈칸이 된다(실제로 겪은 버그).

## 그래픽 텍스트 (글꼴이 아닌 것)

메뉴·옵션 라벨과 배너는 **미리 그려진 raw 4bpp 비트맵**이다(TIM 헤더 없음, 압축
없음). HAGECHO 안에 흩어져 있고 라벨마다 폭이 다르다. 카탈로그는
`work/analysis/menu_strips_catalog.json`(52개), 번역표는
`workspace/scripts/render_menu_strips.py`의 `TRANSLATIONS`에 있다.

배너 TIM(`0x33578`) 안의 단어 3개(골·넥스트 스테이지·로딩 중)는
`workspace/config/banner_words.json`이 박스를 소유한다.

**패치 규칙(중요)**: 박스 전체를 지우면 안 된다. 게임이 같은 텍스처에서 그리는
배경판·장식(다른 팔레트 인덱스)까지 파괴된다. **그 박스의 최빈 잉크 인덱스와 같은
픽셀만** 지우고, 새 글리프는 원본이 배경(0) 또는 그 잉크였던 자리에만 쓴다.

## 그래픽 위치를 찾는 방법 — LoadImage 추적

덤프를 떠서 디스크와 마스크 매칭하는 방식은 검색 영역·임계값이 추측이라 수확이
급감한다(17→31→38→42→47). **게임에게 직접 묻는 방식**을 쓴다.

```
python workspace/scripts/trace_loadimage.py --session <이름> --duration 900
```

ARA `0x8008C2D8`이 `LoadImage(RECT *a0, void *a1)`다. 중단점을 걸면 업로드마다
**목적지 RECT·소스 주소·픽셀 96바이트 지문**이 기록된다(20초마다 중간 저장).

분석 시 반드시 지킬 것:

- **주소가 아니라 지문으로 디스크를 검색한다.** 컨테이너 블록은 각자 다른 주소에
  로드되므로(관측된 것만 6종) 델타 하나를 가정하면 다른 블록 그래픽이 조용히
  걸러진다. 실제로 이 실수로 한 세션을 통째로 날렸다.
- **패치된 빌드도 대조 대상에 넣는다.** 이미 한글화한 자산은 원본 파일과 더는
  일치하지 않아 "미해결"로 오분류된다(91건 중 대부분이 이 경우였다).

## 치트 자동 해금

타이틀 치트는 정확한 버튼 조합을 10초 유지해야 해서 사실상 입력이 불가능했다.
`workspace/config/cheat_unlock.json`이 버튼 마스크를 0(무입력), 유지 시간을
1프레임으로 바꿔 **타이틀 진입 시 자동 해금**한다.

| 주소 | 효과 |
| --- | --- |
| `0x800AED24` = -1 | 전 캐릭터 해금 |
| `0x800AECF8` \|= 0x10 | 스페셜 옵션 해금 |
| `0x800D342C` = 2 | 마스터 치트 상태 |

## 대형 인게임 텍스트 = 두 번째 스프라이트 글꼴 (BIGFONT-SPRITE-001)

DMA 경로 가설은 **틀렸다**. 이 단어들은 `LoadImage`로 정상 업로드되고 있었고,
다만 **단어가 아니라 글자 하나씩** 올라가서 단어 통짜로 찾을 때마다 실패한 것이다.

- 정체: 25칸짜리 **두 번째 글꼴**. 문자표는
  `？！ーアィイウエクコジスズダタッテトニノポユヨルン`.
- 업로드: VRAM `(768..816, 32..448)`에 **4열 격자**. 셀 stride `0x480`.
  다쿠텐이 붙은 `ズ ダ ポ`만 56×56이라 고정 stride 워크가 중간에 어긋난다.
- 디스크 위치·VRAM 좌표 전수는 `work/analysis/bigfont_sprite_001.json`이 소유.
- 조립 가능 단어: `スタート！ ポーズ コンティニュー？ イエス ノー ヨーイ ダウン`.
  `クリア！`·`ボーナス`는 `リ`·`ボ`·`ナ`가 없으니 **별도 통짜 그래픽**이다.
- 타격 효과음은 통짜 비트맵이라 별개다 — 아래 절 참조.

## 타격 효과음 한글화 (HITFX-001) — 적용됨

효과음은 조립식이 아니라 **단어 통째로 그려진 4bpp 비트맵**이고, 팔레트를
`0`(투명)·`1`(검정 본체)·`15`(흰 외곽선) **세 값만** 쓴다. 이 세 값만 쓰는지를
지문으로 삼아 추적된 업로드 전체를 걸러 후보를 자동 검출했다(7개 중 글자 4개).

| 디스크 | 크기 | 원문 | 한글 |
| --- | --- | --- | --- |
| `0xB3DBE8` | 48×31 | `バキ` | 빡 |
| `0xB3DED0` | 80×32 | `ボカ〜ン` | 콰앙 |
| `0xB457AC` | 48×32 | `ドカ` | 퍽 |
| `0xB454AC` | 48×32 | 판독 실패 | **미패치** |

`0xB454AC`는 같은 3-인덱스 스타일이라 효과음이 거의 확실하지만 획이 뭉개져
읽히지 않는다. 추측으로 덮으면 글자가 아닐 경우 원화를 파괴하므로 남겨뒀다.

렌더러는 `workspace/scripts/render_hit_effects.py`, 대상·사전조건 해시는
`workspace/config/hit_effects.json`이 소유한다.

**크기 교훈**: 48px 상자에는 한글 **1음절**만 넣는다. 받침 있는 음절은 카타카나보다
획이 훨씬 빽빽해서 2음절을 넣으면 뭉개진다. 80px 상자만 2음절을 받는다.
원본의 낙서풍에 맞추려고 음절마다 기울기(`TILTS`)와 상하 흔들림(`NUDGES`)을 주고,
외곽선은 폰트 스트로크가 아니라 본체에서 2px 팽창시켜 만든다.

### 왜 디스크립터 표를 못 찾았나

부팅 추적에서 `LoadImage` 진입 시 `rect_ptr`가 스택(`0x807FFEA0`)이었다. 즉
**디스크에 RECT 표가 없다**. 호출자 `0x8008C9B4`는 자산 디렉터리 워커이고,
`s2`=소스 포인터가 셀마다 정확히 `0x480`씩, `s4`=행, `s5=4`=열이었다 —
디스크립터 표가 아니라 **격자 루프**다. 표를 찾는 모든 시도가 실패한 이유다.

### 막힌 지점

단어가 **어떤 셀 순서로 조립되는지** 아직 모른다. 실패한 시도:
u8/u16·0/1-기반 인덱스 배열 검색, u16 RECT 4쌍 검색, 절대 RAM 포인터 표 검색.

다음 수순은 업로드가 아니라 **그리기 경로 추적**이다. `スタート！`·`ヨーイ！`는
어트랙트 데모 경기에 나오므로 **무인 세션으로 가능**하다.

## 남은 작업

1. 위 단어 조립 데이터 확보(그리기 경로 추적) → 25칸을 한글 음절로 교체.
2. `クリア！`·`ボーナス` 통짜 그래픽 위치 확정(스프라이트 뱅크 육안 스윕).
3. 타격 효과음 3개 런타임 확인(빌드 반영 완료, 화면 검증 대기) + `0xB454AC` 판독.
4. **엔딩 동영상→크레딧 전환** 구간 미표본(bank-1 상주 리스크 잔여).
5. 폴백 폰트로 그린 글자들의 스타일 일관성 사람 검토.

## 글꼴 문자열은 완결됐다 (STRING-SWEEP-001)

`workspace/scripts/sweep_untranslated_strings.py`가 ARA·HAGECHO **전 바이트**를
훑어 카나 문자열 255개를 뽑았고, **미번역 0개**다(유일한 미포함은 숫자 룩업 테이블
`０１２３…`). 앵커 기반 스캔의 한계는 코퍼스가 아니라 탐색 범위였다.

따라서 **화면에 남은 일본어는 전부 그래픽**이라고 단정할 수 있다. 문자열을
더 찾으러 다니지 말 것.

## 함정 모음 (같은 실수 반복 방지)

- **DuckStation `textures` 루트를 재귀 순회하지 말 것.** 다른 게임의 텍스처 팩이
  섞여 있다. 반드시 `textures/SLPM-86272/dumps`만 읽고 쓴다. (이 사고로 사용자의
  다른 게임 팩 파일 21개를 삭제했고 복구 불가였다.)
- **settings.ini는 해시로 검증하지 말 것.** DuckStation이 종료 때마다 재직렬화해
  해시가 바뀐다. 핵심 설정값 10개를 직접 확인한다(도구에 이미 반영).
- **게임 실행 중에는 빌드가 실패한다**(파일 잠금). 빌드 전 프로세스를 확인한다.
- **긴 세션은 중간 저장이 필수**다. 중단하면 보고서가 안 써져 플레이가 통째로
  날아간다(실제로 15분 세션을 한 번 날렸다).
- VRAM 프로브 1회는 실측 약 21초다. 스케줄 간격을 25초 미만으로 잡으면 세션이
  계획보다 훨씬 길어진다.
