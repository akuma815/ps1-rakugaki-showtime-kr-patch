# Rakugaki Showtime 한글화 작업 인계 — 2026-08-04

## 현재 상태

프로젝트 폴더 초기화, 선행 한글화 이력 조사, PS1 초기 전략 수립, 교체 원본의
정적 무결성과 clean boot 확인, 핵심 파일 추출, HAGECHO 162블록 카탈로그와
컨테이너 라운드트립, 표준 TIM 121개 렌더링, `#005` 글꼴 image/CLUT 업로드와
Options 화면의 실제 texture sampling, Shift-JIS 문자열→글리프 셀→`POLY_FT4`
경로 확인, 두 한글 글리프의 실제 화면 가시성 PoC, 타이틀 테두리 글자 움직임의
기존 구현 재사용 판정, 범용 문자열 renderer 37개 호출처와 1차 문자열 후보
인벤토리, HAGECHO 직접 호출 18곳과 ARA 직접 호출 19곳의 형태 분류를 완료했다.
ARA의 전달 API 2곳에서 확인한 간접 소비자 중 단일 문자열 wrapper caller 16곳은
전부 분류했고 남은 런타임 생산자 2곳도 정적 테이블까지 역추적했다. wrapper
16곳은 모두 source가 해결됐으며 포인터 배열 renderer caller 27곳도 정적 배열과
NULL 경계까지 전부 분류했다. 전달 소비자 43곳은 `unknown=0`이며, 한 글자·별도
reader 누락 감사에서 사망 문구·크레딧·저작권 문구 경로까지 해결했다. 확인된
decoder·atlas builder 기반 동적 텍스트 경로는 `unknown=0`이며, 다음 기술 게이트는
공용 decoder 재매핑과 corpus 기반 255셀 atlas 재구성 전략의 용량 검증이다.
제자리 atlas 확장은 VRAM 경계와 8비트 UV 한계로 배제했고, 고유 글리프 수가 255를
넘으면 정적 2뱅크 hook PoC로 전환한다. 전체 한글 패치 제작은 아직 시작하지 않았다.
확인된 동적 원문 324개는 안정 ID를 가진 UTF-8 BOM 번역 CSV와 원본 참조 manifest로
내보냈다. 분포는 ARA 125개, HAGECHO 199개이며 번역은 324/324 입력됐다. 완료본의
스프레드시트 자동 서식으로 변한 불변 원문 31칸은 백업 후 manifest에서 복원했고 번역
필드는 전부 보존했다. 교정본 재저장 때 같은 불변 원문 31칸의 자동 서식 변환이
재발했으나 두 번째 백업 후 다시 복원했고 편집 가능 필드는 보존했다. 교정된 완성
corpus는 445글리프, 완성형 한글 379개이므로 단일 255셀 atlas를 배제하고 510셀 정적
2뱅크 hook PoC를 선택했다. `TXT-HAG-22634C`의 교정을 확인했으며 번역 감사 blocking은
0행, 비차단 사람 검토 후보는 32행이다.
`FONT-TWO-BANK-POC-001`은 decoder 반환값의 bit 8을 bank로 확장하고 공용 builder가
bank별 tpage를 선택하는 20바이트 제자리 패치를 만들었다. 새 부팅 GDB 추적에서
`0x1DE`가 bank 1·cell `DE`로 도달해 `U=E0`, `V=D0`, `tpage=1E` primitive를 생성했으므로
bank-aware ABI는 runtime PASS다. PoC용 bank 1은 splash 페이지를 임시 공유하므로 최종
상주 설계는 OPEN이다. 전체 TIM 121개와 겹치지 않는 `(704,256)` 페이지를 다음 런타임
점유 감사 후보로 골랐다.
전략은 [precedent-and-strategy.md](precedent-and-strategy.md)와
[hangul-strategy.md](hangul-strategy.md),
자산 근거는 [asset-survey.md](asset-survey.md), 런타임 근거는
[runtime-font-trace.md](runtime-font-trace.md), PoC 판정은
[font-visibility-poc.md](font-visibility-poc.md), 움직임 판정은
[font-motion-assessment.md](font-motion-assessment.md), 모집단 판정은

## 교체 원본 판정

현재 파일은 `Rakugaki Showtime (Japan).bin/.cue`이고 CUE 내부 참조와 실제
BIN 이름이 일치한다.

이전 BIN에서는 LBA 6,855 이후 일부 sector가 표준 MODE2 형태가 아니어서
`HAGECHO.BIN` 말단과 `SYSTEM.CNF`, `CDXA`를 읽지 못했다. 교체 BIN에서는 전체
251,650개 sector가 sync·MODE2·MSF·중복 subheader 검사를 통과했고, 문제 구간을
포함한 초기 6,863개 Form 1 sector의 EDC/ECC 불일치가 0건이다.

ISO directory는 `SYSTEM.CNF`, `CDXA/RAKU_XA1.XA`–`RAKU_XA6.XA`,
`MOVIE/*.STR`까지 정상 순회했다. 이전의 특수/보호 섹터 가설은 현재 입력에서는
기각한다. 2026-08-04 사용자가 교체 BIN/CUE의 clean boot 성공을 확인했다.
에뮬레이터 버전·설정과 공개 보존 DB의 정확한 해시 일치는 미확정이다.

## 폴더 초기화 결과

- `original`: 제공된 BIN/CUE를 원래 바이트 그대로 이동
- `extracted`: 원본에서 재생성하는 추출물 전용
- `workspace`: 자체 작성 코드·설정·테스트·번역 원본 전용
- `work`, `build`: 재생성 가능한 분석 및 빌드 산출물 전용
- `dist`: 원본 전체 이미지가 아닌 배포용 차분 패치 전용
- `docs`: 조사 결론, 판정 및 인계 기록 전용
- `backups`: 수동 편집 전 복구본 전용

## 선행 사례 판정

- Treasure 개발작의 공개 한국어 패치 이력은 확인됐다: GBA
  `Advance Guardian Heroes`, N64 `Sin and Punishment`.
- 둘 다 다른 플랫폼·엔진이므로 Rakugaki Showtime의 구조적 선례로 이식하지 않는다.
- 조사한 공개 PS1 한국어 패치 목록에서는 Rakugaki Showtime 또는 Treasure PS1
  작품의 한국어 패치를 찾지 못했다.
- PS1 `Silhouette Mirage`의 북미 현지화는 같은 개발사·플랫폼 비교 후보일 뿐이다.

## 현재 매체 정책

새 덤프는 정적 raw-sector 검사를 통과했지만, 빌드는 계속 원본 raw BIN 복사본에
Expected Write가 등록된 sector만 적용하는 방식을 기본으로 한다. ISO 재패킹은
파일 성장·재배치가 실제로 필요하고 XA interleave와 LBA 보존을 검증할 때만 연다.
